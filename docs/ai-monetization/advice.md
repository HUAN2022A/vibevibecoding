## 一、先做减法：现在不该做什么

### 1. 不要在模型层创业（除非你能拿到 $10B+）

| 公司 | 收入 | 毛利率 | 状态 |
| --- | --- | --- | --- |
| OpenAI | $40B 年化 | **33%** | **2030 年才现金流转正**，2026 现金消耗约 $27B |
| xAI | <$1B | 未披露 | 融资 $42B，基础设施烧约 $1B/月 |
| Anthropic | 口径冲突 $6B~$65B | 未披露 | 未证实盈利 |

模型层的入场券是几百亿美元，而且**规模越大越不赚钱**——规模最大的 OpenAI 毛利率只有 33%，被推理成本压到（2025 年推理成本 $8.4B → 2026 预计 $14.1B）。

这是一个靠资本市场融资支撑的资本密集行业，不是创业公司的战场。

> 出处：`cases/foundation-models-and-assistants.md`

### 2. 不要自研垂直模型

**Harvey**（法律 AI，ARR $350M，估值 $15.5B，50% Am Law 100 在用）主动**砍掉了自研法律模型**——因为 Google / xAI / OpenAI / Anthropic 的前沿通用模型在 Harvey 自家的 `BigLaw Bench` 上跑赢了它。它转向了多模型路由 + 预配置 agent 工作流。

**结论：应用层的护城河在模型之外。** 这是整个知识库最重要的一条战略结论。

> 出处：`cases/vertical-enterprise.md` → Harvey

### 3. 不要选「下一版基础模型就能内置」的方向

已发生的复制事件：

- **Wayfair 直接复制了 Interior AI** 的功能
- **Suno** 被主流唱片公司起诉，最终不得不用授权合作换取合法性
- **Character.AI** 45M 用户、单次使用 2 小时，最终被 Google 以 $2.7B 拿走模型非独家授权（实质是 acqui-hire）

判断标准很简单：**如果 OpenAI 下个版本顺手就能做，就不要做这个产品。**

### 4. 不要指望 C 端用户养活你

| 产品 | 用户规模 | 付费转化 |
| --- | --- | --- |
| ChatGPT | 900M 周活 | 50M 付费 ≈ **5.6%** |
| Gemini | 750M 用户 | $1.2B 订阅收入 ≈ **0.7%** |
| Character.AI | 45M 用户 | 收入 $50M，ARPU ≈ **$1.1/年** |

独立开发者的经验值是：**免费用户与付费用户的价值差约 1,000 倍**（Pieter Levels）。

**推论**：C 端财务模型必须建立在极小比例的付费用户上，而这部分用户的算力成本往往由你自己承担。

> 出处：`cases/consumer-apps.md`、`cases/indie-bootstrapped.md`

## 二、动手前必须先定的三件事

### ① 谁付钱？

只有三个答案，且决定完全不同的产品形态：

| 付费方 | 产品要求 | 代表案例 |
| --- | --- | --- |
| **终端用户（B2C）** | 需要病毒机制、需要付费墙、C 端算力必须极便宜 | Midjourney（1.4M 付费订阅）、FaceApp |
| **企业（B2B）** | 需要合规、需要销售组织、可按座位/结果收高价 | Harvey、Abridge、Sierra、Glean |
| **广告主** | 需要高价值受众（受众本身要贵） | OpenEvidence（CPM $70-1,000+） |

**如果 C 端算力成本压不住，必须找第二付费方。**

**Cursor** 是这条结论最清晰的证据：它明确披露**大型企业账号毛利为正，个人开发者账号仍然亏损**——靠企业客户补贴个人开发者。

> 出处：`cases/dev-tools.md` → Cursor

### ② 单次成本是多少？

先算这个数字，再决定定价。

**反面案例（收入增长但亏损扩大）**：

| 公司 | 收入 | 亏损 |
| --- | --- | --- |
| Runway（2024） | $44M | **EBITDA -$155M** |
| Synthesia（2024） | $58.3M | **税前 -$59.2M** |

**正面案例**：

| 公司 | 规模 | 效率 |
| --- | --- | --- |
| Midjourney | **$200M ARR** | 仅 40-45 人，从未融资，人均创收约 $4.5M |
| OpenEvidence | $300M 年化 | 毛利率 **90%** |
| Photo AI（单人） | 月收入 $105K | 月利润 $80K，净利率约 **76%** |

> 出处：`cases/creative-media.md`、`cases/indie-bootstrapped.md`

### ③ 护城河在哪？

模型不是护城河。真实可用、且有案例验证的只有五项：

| 护城河 | 案例 | 具体怎么建 |
| --- | --- | --- |
| **专有数据 / 独家内容授权** | OpenEvidence | 签下 NEJM、JAMA、Wiley、Cochrane、NCCN、ACC 的独家授权 |
| **工作流嵌入深度** | Abridge | 成为**首个集成进 Epic EHR** 的环境 AI 工具，领先竞品 3-6 个月 |
| **合规与资质** | Synthesia | SOC 2 / GDPR / ISO 27001 / **ISO 42001**，把合规变成涨价理由 |
| **分发渠道** | Grok（X 免费引流）、Gemini（搜索内嵌）、Perplexity（Motorola / Airtel / Snap） | 提前谈渠道，用股权/分成/补贴换接入 |
| **权限治理** | Glean | 企业敢用的原因不是「更聪明」，而是「不泄密」+ 引用可溯源 |

> 出处：各案例卡片的「护城河」字段

## 三、已被验证、客户真在付钱的赛道

| 赛道 | 代表 | 收入 | 付费方与定价 | 为什么能收到钱 |
| --- | --- | --- | --- | --- |
| **编码** | Cursor | $4B 年化 | 座位制 $20-200/seat | 增速最快：$1M→$500M ARR 是史上最快 SaaS |
| **编码** | Claude Code | $2.5B 年化 | 捆绑订阅 | **一个季度从 $1B 到 $2.5B** |
| **法律** | Harvey | $350M ARR | 座位制 | 席位中位数**12 个月翻倍**，50% Am Law 100 |
| **医疗文书** | Abridge | $100M ARR | 按医生计费 **$2,500/人/年** | 集成进 Epic = 默认地位 |
| **医疗决策** | OpenEvidence | $300M 年化 | **药企广告** + 企业合同 | CPM $70-1000+（社交媒体仅 $5-15），毛利 90% |
| **客服** | Sierra | $200M ARR | **按成功解决计费** | 覆盖 40% Fortune 50，79× 估值倍数 |
| **销售 GTM** | Clay | $150M ARR | 双计量订阅 | YoY **+260%** |
| **企业搜索** | Glean | $300M ARR | 座位制 $100K-500K/单 | 9 个月 ARR 翻倍，NRR 驱动 |
| **创意视频** | Synthesia | $146M ARR | Credit 计量 | NRR **>140%**，90% Fortune 100 |
| **数字人视频** | HeyGen | $205M ARR | $24/月无限量 | 病毒系数 >3.0，运营利润率约 20% |

**共同点**：几乎全是 **B2B**，都有**可枚举的使用者角色**（律师、医生、工程师、客服），都能按**座位或结果**计价。

**赛道选择检查清单**：

- [ ] 使用者是组织内的可枚举角色吗？（律师/医生/工程师/客服 = 是）
- [ ] 这个角色原本的人力成本高吗？（Abridge $2,500/年 vs 医生时薪 = 明显划算）
- [ ] 有客观的「成功」定义可以计价吗？（Sierra 可以，通用助手不行）
- [ ] 采购决策者和使用者是否分离？分离意味着可以绕开采购先做渗透（OpenEvidence 路径）
- [ ] 客户的合规要求高吗？高 = 可以做合规溢价（Synthesia 路径）

## 四、定价模式的四条硬经验

### ① 当成本和价值发生在不同环节，一定要拆成两个计价表

**Clay 2026-03 的改造**：把单一 credit 模型拆成

- `Data Credits` → 支付第三方数据增强与 AI/数据成本
- `Actions` → 计量工作流执行步骤（HTTP 调用、CRM 同步、AI 任务、序列发送）

结果：

- 多数原生增强成本下降 **50-90%**
- **失败查询不再收费**
- CRM 同步 / HTTP API / Web Intent 从 $800 Pro 档下移到新的 **$495 Growth 档**
- 客户自带 API key 时，公司仍能对「编排」收费

**这是整个知识库里最可复用的一条技巧。** 当成本与价值发生在不同环节时，用一个计价表一定会算错账。

> 出处：`cases/vertical-enterprise.md` → Clay

### ② 按结果收费是 AI 服务唯一说得通的模式

**Sierra** 的定价：按对话量 或 **按成功解决（pay-per-resolution）**。

客户不关心你用什么模型，只关心问题有没有解决。把定价与「成功解决」绑定，等于把 AI 的不确定性风险**从客户转移到自己**——所以它敢要高价，以至于估值 / ARR 达到 **79×**（$15.8B / $200M）。

**前提**：你的准确率必须足够高，否则按结果收费会亏穿。

### ③ 「无限量」和「计量」都能赢，取决于成本可预测性

| | HeyGen | Synthesia |
| --- | --- | --- |
| 定价 | **$24/月无限生成** | 按 credit 计量 |
| ARR | $205M | $146M |
| 毛利 | 被上游决定（语音依赖 ElevenLabs、实时语音依赖 OpenAI） | **70-80%** |
| 估值 | $500M | **$4B** |
| 路线 | 自下而上，SMB 与个人创作者 | 企业优先 |
| 运营利润率 | 约 20%（2023 Q2 即盈利） | 2024 年税前亏损 $59.2M |

**规则**：**没有上游依赖就敢无限量，有上游依赖就必须计量。**

### ④ 版权/监管风险可以转成变现工具

**Suno** 被主流唱片公司起诉，最终与 Warner Music Group 达成合作，条款包括：

- 免费层歌曲**不可下载**
- **下载需要付费账号**
- 付费层设月度下载上限，可**加购**下载额度

把合规成本直接设计成了付费转化抓手。

> 对比：**OpenAI 也做了类似的事**——广告只投在 Free/Go 层，Pro/Business/Enterprise 保持无广告，用「无广告」给付费层创造差异。

## 五、分发：现在比产品更难

所有做过的人都指向同一件事。

**Pieter Levels 2026 年的原话**：*「现在所有人都能用 AI 做出应用，所以真正的挑战变成了分发。」*

他自己的解法：182,462 名邮件订阅者 + X 上十亿级曝光 + 播客曝光。

### 可以抄的分发手段

| 手段 | 案例 | 关键设计 |
| --- | --- | --- |
| **免费产出物带水印** | HeyGen | 病毒系数 **>3.0**，另加 **20% 联盟佣金**，由 Affiverse 代理管理 |
| **免费给专业人士，绕开采购** | OpenEvidence | 绕开医疗 **18 个月**采购周期，先做到 **40%+ 美国医生**渗透率，再回调向上攻医院 |
| **大规模免费期换习惯** | Perplexity × Bharti Airtel | 3.6 亿用户免费获 12 个月 Pro，免费期结束后印度付费收入在半年内涨约 **60%** |
| **给渠道方股权换接入权** | Abridge × Epic | 给 Epic 股权 + 持续收入分成，换来对使用 Epic 的 38% 医院网络的优先接入 |
| **设备预装** | Perplexity × Motorola | 按设备激活拿量，捆绑 3 个月 Pro |
| **母体平台免费导流** | Grok × X | 4 亿 X 用户，**几乎零获客成本** |
| **内嵌他人产品** | HeyGen × Canva | 插件形式触达 Canva 的 1.5 亿月活，用户无需迁移到独立平台 |
| **白标转售** | HeyGen | 被 Reply.io、Icon.me 白标转售 |
| **免费入口 + 极简实现** | Photopea / Remote OK | 免费工具做入口，靠广告/订阅/职位发布变现 |

### 反例：不要指望「更好的产品」自动带来用户

- 「独立开发者做出了漂亮的 AI 工厂，但没有钱也没有流量」（Pieter Levels，2026-06）
- 「独立开发者可能最先灭绝，因为 AI 降低了执行成本」（2026-07）
- 「AI 提升了所有人的应用质量，但客户现在会自己 vibe code 一个克隆来跳过付费」（2026-07）

## 六、建议的行动顺序

```text
1. 先选付费方（B2C / B2B / 广告主），再想产品
2. 算清单次推理成本 × 重度用户用量，和订阅价对比
3. 设计免费层：能独立产生价值（否则没人传播）
              但无法满足重度需求（否则没人付费）
4. 选计价单位：成本与价值不同环节 → 拆两个计价表（Clay 模式）
5. 如果 C 端压不住成本 → 找第二付费方（企业 / 广告主 / 收购方）
6. 确认护城河属于五项之一，并假设自己会被复制
7. 用极简架构压成本：Pieter Levels 年 40 亿请求只花 $244/月
8. 把分发当作和产品同等重要的事，且要在开发前就开始
```

### 关于第 7 点的具体数据

| 项 | Pieter Levels 的实测值 |
| --- | --- |
| 年请求量 | **40 亿次** |
| 托管成本 | **$244/月**（2026-04） |
| 技术栈 | 单 VPS + 原始 PHP，无框架、无微服务 |
| Photo AI | **40,870 行 index.php** → 月收入 $105,000 / 月利润 $80,000 |
| Remote OK | 单一 PHP 文件 → 单月 $101,101（2021-04） |
| Nomad List + Remote OK + MAKE | 月收入 $34,733 / 月支出 $3,950（2017-08） |

**利润率来自极简架构，不来自定价。** 绝大多数 AI 应用死在云账单上，而不是死在需求上。

## 七、必须说明的局限

1. **这些是从历史数据推断的，不是保证。** 知识库基准日 2026-09-14，AI 行业数据半衰期很短，**建议每季度复核一次**。

2. **复制已经成功的模式可能已经太晚。** Cursor 从 $1M 到 $500M ARR 只用了不到两年——这说明窗口期极短，也意味着你看到的成功案例，赛道内可能已有 20 家在打。

3. **Anthropic 的收入数据在本知识库中标记为 D 级（不可用）。** 存在把 $65B 融资额与 $65B ARR 混淆的疑点。任何涉及它的市场规模推算都不可靠，参见 `sources.md` 待核实清单。

4. **单干是可行的，但成功率约 5.7%**（Pieter Levels：70+ 个项目只成 4 个）。可行的前提是**每次验证成本 <$1,000、<2 周**，靠数量取胜。如果你的验证周期是几个月，这个模式不成立。

5. **10 条风险清单**（完整版见 `patterns.md`）：推理成本吞噬毛利、上游依赖、平台内置、版权合规、口径污染、估值倍数过高、消费者付费意愿低、免费层成本无法覆盖、分发瓶颈、补贴期后转化未知。

6. **本文件的建议偏向 B2B。** 这是数据分布决定的——B2B 案例有更清晰的收入与毛利数据；B2C 案例（Character.AI、FaceApp）呈现的是低 ARPU 与高不确定性。如果你的优势在 C 端，请把这理解为「C 端更难，而不是不能做」。

## 附录：可行性自检表

在产品立项前逐条打勾，任何一项为「否」都需要有明确应对方案。

| # | 检查项 | 通过的标志 | 失败信号 |
| --- | --- | --- | --- |
| 1 | 单位算力成本 | 单次使用推理成本 << 单用户订阅费 | 重度用户成本超过其付费额，且无企业方补贴 |
| 2 | 付费方明确 | 能一句话说清谁付钱、付多少 | 只能说「先做起来再想变现」 |
| 3 | 免费层设计 | 能独立产生价值，但无法满足重度需求 | 免费层就够用（没人付费），或免费层没用（没人传播） |
| 4 | 计价单位 | 与价值创造环节对齐 | 成本与价值发生在不同环节却用一个计价表 |
| 5 | 分发渠道 | 已有受众 / 自带病毒机制 / 可嵌入他人产品 | 需要持续买量 |
| 6 | 护城河 | 属于五项之一（数据/工作流/合规/渠道/治理） | 只能回答「我们的模型效果更好」 |
| 7 | 上游依赖 | 关键环节自主可控，或有成本保底 | 核心能力依赖单一供应商且无议价权 |
| 8 | 基础设施复杂度 | 单机可承载，偶发故障可接受 | 需要多服务、GPU 常驻、弹性扩缩 |
| 9 | 失败成本 | 验证成本 <$1,000、<2 周 | 需要数月才能验证 |
| 10 | 被复制风险 | 有数据/内容/渠道壁垒 | 基础模型下一版就能内置 |
| 11 | 合规准备 | 已明确目标行业的认证要求与周期 | 客户是受监管行业但没考虑合规成本 |
| 12 | 结果可计量 | 能定义「成功解决」并计数 | 价值无法客观衡量，只能按时间/席位收费 |
